# シフト作成アプリ

店舗向けの週間シフト作成PWAです。iPadでの操作と、A4横1枚での印刷を主な用途として設計しています。

公開版: https://kazutake1.github.io/shift-webapp/

## 主な機能

- 月曜日から日曜日までの週間シフト作成
- 6:00〜翌朝6:00の勤務時間入力
- 従業員①・従業員②・予備従業員の3段構成
- 固定作業、不定期作業、トレーニング、備考
- 複数店舗の切り替え
- 従業員のフルネームとシフト表用表示名の分離
- 従業員検索（名前・シフト表名・従業員番号）
- 同一従業員の勤務時間重複警告
- 直前1回のUndo
- 誕生日通知
- 設定 →「従業員リスト」から開く年次の誕生日・プレゼント対象者リスト／渡し済みチェック
- A4横の印刷プレビュー・印刷
- 暗号化バックアップと復元
- PWA / Service Workerによるホーム画面起動・オフライン起動

## データ保存

通常のシフトデータはサーバーへ送信せず、ブラウザーの `localStorage` に保存します。

- シフトデータ: `shift-ipad-stores-v2`
- 最終バックアップ作成日時: `shift-last-backup`

同じ端末でも、ブラウザーやブラウザープロファイルが変わると別の保存領域になります。ブラウザーのデータ削除でも失われるため、定期的なバックアップを前提としています。

### 複数画面での同時編集

同じブラウザーで複数タブ・複数ウインドウを開き、別画面でデータが更新された場合は、その画面からの保存を停止します。古い画面から最新データを上書きする事故を防ぐためです。

競合を検知した場合は、アプリを開き直して最新データを読み込んでください。

## バックアップ

バックアップには全店舗のシフト、従業員、固定作業、備考などが含まれます。

新しいバックアップは端末上で暗号化してから `.shiftbackup` ファイルとして保存・共有します。

- 暗号方式: AES-256-GCM
- 鍵導出: PBKDF2-HMAC-SHA-256
- PBKDF2反復回数: 600,000
- パスワード: 8文字以上
- パスワード自体は保存しません

パスワードを忘れると復元できません。

「最終バックアップ作成」はファイルを作成した日時です。保存先にファイルが現在も存在することまではアプリ側では確認できないため、作成後に端末の「ファイル」アプリなどで確認してください。

以前の暗号化されていないJSONバックアップも復元できます。

## シフト表の重要仕様

シフト表は印刷結果と密接に連動しているため、変更時は特に注意します。

- A4横・1週間1枚
- 月曜日〜日曜日
- 6:00〜翌朝6:00
- 1日5段
  1. 固定作業
  2. 従業員①
  3. 従業員②
  4. 予備従業員
  5. 不定期作業／トレーニング
- 土曜日は青、日曜日・対応済み祝日は赤
- 印刷時は用紙内で縦方向中央配置
- 太罫線は表の実測座標を使ったSVGレイヤーで描画

表のレイアウト、罫線、文字サイズ、印刷寸法を変更すると印刷崩れにつながるため、表本体の変更は必ず回帰確認を行います。

## 開発・テスト

Node.js 20を基準にしています。

### 構文チェック

```bash
npm run check
```

### 回帰テスト

```bash
npm test
```

### ブラウザー実操作テスト

GitHub ActionsではPlaywrightを一時インストールしてChromiumとWebKitの両方で実行します。

ローカルで実行する場合は、Playwrightを用意したうえで:

```bash
npm run test:e2e
```

現在の自動テストでは、勤務時間、週コピー、店舗データ、バックアップ暗号化、保存失敗時のロールバック、複数画面競合、バックアップ復元、従業員検索、勤務重複警告などを確認しています。

## 公開

`main` ブランチをGitHub Pagesの公開元として使用しています。

変更時の基本手順:

1. 最新の `main` を基準にする
2. 指定された範囲だけ変更する
3. `npm run check`
4. `npm test`
5. Chromium / WebKitの実操作テスト
6. `main` へ反映
7. GitHub Pagesのデプロイ成功を確認
8. 実機で必要箇所を確認

PWAのランタイムファイルを変更した場合は、`sw.js` のキャッシュ版も更新し、利用端末が新しいファイルへ切り替わるようにします。

## 既知の制約

- 祝日データの収録は現在2026年・2027年です。
- 通常データはブラウザー内保存で、サーバー同期はありません。
- GitHub Pages上では `https://kazutake1.github.io` が同一オリジンです。他の同一オリジンアプリとの保存領域の完全な分離には、将来的に専用ドメイン／サブドメインが有効です。
- Undoは直前1回です。
- バックアップ作成後、保存先にファイルが残っているかはアプリから確認できません。

## セキュリティ上の方針

- 外部サービスへシフトデータを送信する処理は追加しない
- DOMへユーザー入力を表示するときは原則 `textContent` を使用する
- 保存処理は共通経路を通し、複数画面競合時は停止する
- バックアップ復元前に形式を検証する
- 暗号化バックアップのパスワードは保存しない
- 新しい保存経路を追加するときは、競合防止と保存失敗時の挙動をテストする

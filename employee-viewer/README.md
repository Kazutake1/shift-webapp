# 従業員用「所属店舗のシフト表だけ」閲覧 — 非公開の設計・検証

## 2026-11-15 仕様更新
- **従業員番号とパスワードによるログイン案を撤回する。**
- **「自分のシフト」ページを作らない。**
- 従業員には **所属店舗の確定済みシフト表全体** だけを表示する。個人別一覧、勤務希望、従業員検索、従業員台帳、編集・削除画面、他店舗への切替は実装しない。
- 管理者用の既存ページは従業員に渡さない。専用サイトは **必ず別オリジン** に配置する。管理者のGitHub Pagesと同じ `*.github.io` オリジンのサブフォルダには置かない。

## 重要な安全上の境界
1. 管理者の `shift_app_state` や `localStorage` のデータを従業員サイトから読む設計にしない。既存のクラウド同期データ `projectScheduleRoot()` も、`employeeId`・過去週などを含むため **そのまま渡さない**。
2. `projection.mjs` は **管理者側/信頼できる公開処理専用**。社員一覧を一時的に参照して表示名を解決した直後に、必要最小限のデータだけを返す。従業員配信用には同モジュールや元データを含めない。
3. `projectEmployeeScheduleWeek` は未確定週を必ず `null` とし、現在の確定済み週の `week.days` を投影する。確定後に管理者が修正したシフトも反映対象。
4. 配信データの許可リスト: `format`、`storeName`、`weekStart`、7日分の `date`、`shifts`/ `training` 内の `position`・`band`・`name`（シフト名）・`start`・`end`。
5. 不許可: フルネーム、従業員番号、従業員ID、誕生日、入社日、退職日、所属情報、従業員一覧、管理者の認証情報、管理備考、確認履歴、自由入力の業務文言。シフト名とフルネームが一致する場合は「従業員」に置換。
6. シフト名そのものが個人識別情報になり得る。管理者が従業員向けの表示名を事前に確認し、フルネームや機微情報を入れない。文字列だけで完全な判定はできないため、公開前の確認を必須とする。
7. 店舗別アクセスは画面の切替ボタンの非表示だけでなく、**認証されたユーザーIDと店舗との対応をサーバー側で検査**。URL、クエリ、APIを改変しても他店舗のシフトを読めないようにする。
8. 閲覧者にはデータ変更権限なし。未認証者は拒否。退職者等はアクセス権の停止後、データを取得できないようにする。ページやAPIレスポンスは原則として秘密情報のない最小構成とし、個人別の管理情報は保管しない。

## ログイン方法について
従業員番号・固定パスワードは使わない。安全な代替案として、**管理者が事前に登録した従業員だけが、メールの使い捨てログインリンクで認証する方式**を第一候補とする（実装・運用方法は未確定）。
URLを知るだけで誰でも見られる公開リンク方式は採用しない。共有の店舗パスワードも退職者ごとの停止が難しいため推奨しない。
この設計は「自分のシフト」ページや従業員番号によるログインを復活させるものではない。

## 今回実装した範囲
- ✅ 管理者側の純粋関数 `projection.mjs`：確定済みシフト表全体から閲覧専用データを生成。
- ✅ 架空データだけを使った単体テスト：未確定拒否・不要な個人情報の排除・シフト名の匿名化・確定後変更・店舗分離・不正入力を検証。
- ❌ 従業員向けログイン、データベースの専用テーブル・RLS、Web画面、配信・自動更新・公開処理は **まだ未実装**。
- ❌ Supabase本番のテーブル・ポリシー・権限、既存アプリ、GitHub Pagesの公開内容は **変更していない**。

## 本番導入前の必須作業
1. 選択した認証方法に合わせ、管理者用データへアクセスできない **独立した閲覧専用データ経路** を作成する。別Supabaseプロジェクトか、十分に検証した専用テーブルと権限を比較して決定する。
2. データベースの `GRANT` と `RLS` を最低権限で設定。未認証・他店・退職者・読み取り以外の API アクセスを自動テストで拒否する。管理者用 `shift_app_state` も閲覧者にアクセス不可を確認する。
3. 管理者のみが閲覧用データを送信できる仕組みを実装。確定・確定後編集の際に同期し、オフライン時は未公開として明示。**シフトの自動確定がブラウザ起動に依存する場合、サーバー側の公開も自動とは断定できない**。
4. スマホ版閲覧専用サイトを**管理者アプリとは異なるオリジン**に構築。閲覧のみで、画面・コード・ストレージ・APIのどこにも従業員台帳を含めない。
5. 公開前の独立レビュー、誤配信防止、所属店舗・権限削除、画面/APIの不正アクセス試験を通過させる。本人の了承なく本番へ公開しない。

## 運用上の注意
従業員サイトで公開するシフト名・勤務日時も、従業員間で互いの勤務状況を知る情報となる。閲覧可能者と表示範囲を店舗内で明示する。URLや画面写真の転送による二次共有は技術だけでは防げない。
